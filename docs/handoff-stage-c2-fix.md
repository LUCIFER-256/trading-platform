## 1. Production defects found by reading the code (fix all; each needs the killing test in section 4)

D1. `circuit.productAssertionsPassed()` is never called, so a half-open circuit can never settle. Call it after the REST assertions complete for all active, non-halted instruments, before opening the socket.
D2. The circuit's events (`reconnect`, `failedAttempt`, `recovery`, `remediationRequired`) are supplied by whoever constructs the circuit, and the session never receives them, so a heartbeat timeout reconnects nothing. Add to `session.ts` a `CircuitEventRelay` class (implements `CircuitEvents`, with `bind(handlers)`); the session binds itself in its constructor. `reconnect` closes the transport and schedules a backoff reconnect; `recovery`, `failedAttempt`, `remediationRequired` write safe records. Tests build the circuit with the relay, then the session with the same relay.
D3. One disconnect is counted as several failed attempts: the transport reports `failed` and then `closed` for the same socket (a ws `error` is always followed by `close`; a 1009 close fires both callbacks), and a session-initiated `close()` (malformed threshold, ahead-confirmed, queue recovery, heartbeat) fires `closed`, which calls `failure("NETWORK")` again and schedules a second backoff. Fix: give every connection a number; the first terminal event of a connection (failed, closed, or a session-initiated close) wins, and every later callback of the same connection is ignored. A session-initiated close counts failed attempts only through the circuit's own rule for that reason and never adds a "NETWORK" failure.
D4. After a TLS/AUTH failure the following `closed` callback schedules a backoff reconnect, defeating the 30-minute remediation rule. Fixed by D3 plus D5.
D5. When `connect()` is blocked by the circuit (`mayAttemptConnection()` false) nothing ever retries, so after the circuit opens the session is dead. Ruling R12: while blocked, re-check every 1,000 ms using the injected scheduler; one timer at most; the first re-check at which `mayAttemptConnection()` is true attempts the connection. (OPEN lasts 30,000 ms; auth/TLS 1,800,000 ms; HALF_OPEN permits exactly one attempt.)
D6. HTTP 429 handling. Upgrade 429: the transport must destroy the pending response/request (a ws `unexpected-response` listener leaves the socket hanging unless you do) and the session waits exactly the `Retry-After` seconds (60,000 ms when absent or invalid, via `retryAfterMs`), then attempts once; the later `closed` must not replace that timer (D3). REST 429 in `assertAll`: the whole connect attempt stops, the circuit records it through `http429`, and a retry is scheduled after the same delay; today the instrument is silently skipped and nothing retries.
D7. REST statuses. Ruling R13: status 404, or a 200 body that fails `validateProductAssertion`, opens `PRODUCT_ASSERTION_FAILURE` for that instrument only. Any other non-200 status (5xx etc.) and any exception thrown by the fetcher is a transient failure: no halt, one failed attempt via `circuit.connectionFailed("REST")`, backoff reconnect. Today a 500 opens a durable halt that needs a human.
D8. Queue recovery. The queue's `failedAttempt` currently only logs. It must call `circuit.connectionFailed("PERSISTENCE")` exactly once per recovery. The `transitionState(... UNAVAILABLE_PERSISTENCE ...)` calls are fire-and-forget and an exception becomes an unhandled rejection: await them inside a catch that records the safe code `PERSISTENCE`.
D9. The backoff attempt counter never resets, so the delay is stuck at the 30,000 ms cap forever. Ruling R14: reset the counter to 0 when a heartbeat returns `ACCEPTED` on the current connection (a live, in-sequence connection).
D10. A halt opened inside a connection (match gap, price jump, locked quote) is not told to the circuit, so a half-open readiness window waits for a valid ticker from an instrument that is halted and can only time out. Add the authorized `markHumanHalted(instrumentId)` to `ProviderCircuit` (section 3) and call it from `halt()`.
D11. Frames for a human-halted instrument are recorded as `DISABLED_OR_UNMAPPED` with a null instrument: wrong reason. Ruling R15: drop them with no quality record, no persistence call and no circuit call. Frames for a symbol that is not active at all stay `DISABLED_OR_UNMAPPED` with a null instrument.
D12. Unhandled rejections: `void this.connect()` and `void this.frame(frame)` leave any exception (for example `openHalt` rejecting) unhandled, which crashes the process. Catch both; record the safe code `PERSISTENCE` (or `NETWORK` for connect), count one failed attempt, and schedule a backoff reconnect. Never include the error message in a record.
D13. The endpoint scheme is only checked inside the transport, after the REST calls. `connect()` must validate the endpoint first (`wss:` only): on failure record the safe code `CONFIGURATION`, make no REST call and open no socket, and never throw out of `connect()`.
D14. Transport. (a) Oversize frames: ws reports an oversize frame as an `error` whose `code` is `WS_ERR_UNSUPPORTED_MESSAGE_LENGTH`, and the local `close` code is normally not 1009; map that error code to `PAYLOAD_TOO_LARGE` and keep the 1009 mapping. (b) Add an injectable `socketFactory?: (url: string, options: object) => SocketLike` to `WsTransportOptions` (default: the real `ws`), with `SocketLike` the small subset used (`on`, `send`, `close`). This makes the transport unit-testable without ports and is the only transport API change. (c) Production code must never set `rejectUnauthorized`, send an `Authorization`, cookie or custom header, or request an extension.
