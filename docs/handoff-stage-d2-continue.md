## 2. Findings that change the plan (verified by the auditor against the migration; use them)

- The previous builder said the startup procedure is blocked. It is not. `platform.list_open_market_data_halts()` is granted only to `platform_market_data_operator`, so do NOT use `listOpenMarketDataHalts` from the engine. But `platform.market_data_startup_recovery(instrument uuid)` IS granted to `platform_market_data` and returns, per instrument, the unresolved halt (`halt_id`, `halt_reason_code`), the last accepted price and event time, and the newest unconsumed unexpired jump reset. It returns NO row for an instrument with no state row: treat that as a fresh start (no seed, no halt).
- Policyless, disabled-provider, disabled-market, disabled-instrument and disabled-mapping instruments are already excluded by the D1 catalog query in `PostgresPersistencePort.fromCatalog` (inner joins on enabled flags and `market_data_policies`). Do not duplicate that query's logic differently: reuse the mapping, and for the skipped list compare the configured engine instruments against the mapped ones. To give a precise safe reason (`NO_POLICY`, `DISABLED_SCOPE`, `HUMAN_HALT`), you may read only the granted columns listed above.
- **R21 (user approved 2026-10-26):** the engine reads restart state through `marketDataStartupRecovery` as exported by the repository, unchanged. `eventAt` arrives as a JavaScript `Date` (millisecond precision). Convert it to the session's microsecond string as `BigInt(date.getTime()) * 1000n`. The truncation can only make the restart check more lenient by under 1 ms and the database enforces microsecond regression on append anyway. Document this in a comment-free way: add a unit test `startupSeedTruncatesEventTimeToMilliseconds` that proves the conversion and that a ticker one microsecond after the seed is accepted.
- The unit tests in `advisory-lock.test.ts` and `terms-gate.test.ts` carry the names the plan reserves for the user-run PostgreSQL tests (`advisoryLockAllowsSingleWriter`, `advisoryLockLossAbortsEngine`). Rename the UNIT cases with a `unit` prefix (for example `unitAdvisoryLockRefusesSecondWriter`) so a passing unit run is never mistaken for the real-database evidence. `persistenceRefusesBeforeTermsGate` is a pure unit test and keeps its name.
