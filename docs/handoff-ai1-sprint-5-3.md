## 2. Contract gaps the auditor found by reading both sides (verify each; do not trust)

G1. **Identifier mismatch.** The port and session use symbolic ids (`providerId: "coinbase"`, `instrumentId: "btc"`, quality `flushId: "quality-1"` from an in-memory counter). The SQL functions take UUIDs for provider, instrument and flush id. A mapping layer built from the catalog at startup is required, and the quality flush id must be a UUIDv7 that stays identical across retries of the same bucket (idempotency) and cannot repeat across process restarts.
G2. **Halt reason typing.** The port's `reasonCode` is a `string`; the repository accepts only the union `LOCKED_OR_CROSSED | OUT_OF_ORDER_MATCH_ID | IN_SESSION_MATCH_GAP | PRICE_JUMP | PRODUCT_ASSERTION_FAILURE | IDEMPOTENCY_CONFLICT`. An unknown reason must fail loudly (and safely), never be coerced.
G3. **Restart state.** The session starts with an empty ticker state and empty halted set. After a restart, the engine must (a) pass `humanHalted` from `listOpenMarketDataHalts`, and (b) seed the price-jump reference from `marketDataStartupRecovery` (last accepted price and event time). The session has no way to accept that seed today: see R19.
G4. **Transition during outage.** When the database is down, `transitionState(UNAVAILABLE_PERSISTENCE)` itself fails. That is by design: the database clock makes the data stale within `max_ingestion_age_ms` with no cooperation from the engine. The adapter must not hide the failure and must not retry unboundedly.
G5. **Deadline ownership.** The queue owns the 1,000 ms per-call deadline (R2/R3/R4/R9). The adapter must not add retries or its own timeout, but it must not leave a database connection checked out forever when the queue abandons a hung call.
